🔍 ROOT CAUSE ANALYSIS
─────────────────────
ROOT CAUSE: `ts-execute-service` fails on `GET /api/v1/executeservice/execute/execute/{orderId}` with HTTP 403. The request contains a double-URL-encoded `%25` sequence in the path. Spring Security's `StrictHttpFirewall` rejects it as a malicious pattern.

FIX: In `ts-execute-service`, either:
1. Remove double-encoding from the client request path (do not encode `%` as `%25`).
2. Configure `StrictHttpFirewall` to allow `%` in URLs by overriding `StrictHttpFirewall.setAllowUrlEncodedPercent(true)`.
3. Add `StrictHttpFirewall` bean with relaxed validation for percent-encoded sequences.

Immediate action: Ensure `{orderId}` is passed as a single-encoded value, e.g., `12345` not `%12345`.
