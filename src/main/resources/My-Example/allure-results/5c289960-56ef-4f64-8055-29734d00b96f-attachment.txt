🔍 ROOT CAUSE ANALYSIS
─────────────────────
**ROOT CAUSE:**
The failure occurs in `ts-admin-travel-service` during a DELETE request to `/*` endpoint. The service rejects the request with HTTP 403 due to `RequestRejectedException` thrown by Spring Security's firewall, specifically because the URL is not normalized (contains malformed path segments like `..` or `%2e%2e`).

**FIX:**
Configure `ts-admin-travel-service` to allow normalized URLs by either:
1. Adding a custom `RequestMatcher` in Spring Security that permits the DELETE endpoint
2. Configuring `HttpFirewall` to permit the specific URL patterns used by the API
3. Ensuring client requests use properly encoded, normalized URLs

The gateway service should normalize URLs before forwarding to the admin service.
