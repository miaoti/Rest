\begin{abstract}
Black-box REST API testers sample inputs from the OpenAPI spec and stop at the HTTP status class, so they miss failures that only appear across services: a \emph{soft error} returned in a 2xx body, and a \emph{hidden downstream failure} where the gateway returns 2xx while a service deeper in the call tree has 5xx-errored and the error was swallowed. We present \textbf{MIST} (Microservice Integration \& Scenario Tester), an open-source tool that turns OpenTelemetry/Jaeger traces and OpenAPI specs into runnable cross-service workflow tests and checks them with a \emph{trace-shape oracle}. MIST drives only externally-reachable entry points and reads internal behaviour off the trace (\emph{Root API Mode}); injects exactly one fault per negative variant, keyed on \texttt{(rootApi, paramName, paramLocation)} so each parameter location enrols independently (\emph{Sniper Strategy}); and evaluates each captured trace against learned-then-checked invariant families over the trace metadata that survives production PII-stripping, several of them label-free and LLM-free. One, \textsc{HiddenDownstreamFailure}, fires when a clean 2xx hides a server-errored downstream span --- caught structurally from the trace, independent of the response body. A bundled demo runs from one properties file on four microservice systems (TrainTicket~\cite{Zhou2021TrainTicket}, Istio Bookinfo, Sock Shop, Online Boutique) with no code changes; the trace-oracle verdicts reproduce offline from committed traces, while the live-SUT execution path additionally needs the SUT deployed and a JDK. On TrainTicket MIST detects all 10 injected faults across 15{,}036 generated test cases; on Bookinfo and Online Boutique its trace oracle catches a real downstream failure swallowed behind a \texttt{200} --- over HTTP and gRPC --- that status, schema, and body-level oracles pass. Source: \url{https://github.com/miaoti/Rest/}. Screencast: \todo{SCREENCAST-URL}.
\end{abstract}

\section{Introduction}\label{sec:intro}

Modern REST API testers are spec-bound and oracle-light. Spec-only generators~\cite{Arcuri2019EvoMasterTOSEM,Atlidakis2019RESTler,MartinLopez2021RESTest,Liu2022MoRest,Kim2023ARATRL,Corradini2024DeepREST,HatfieldDodds2022Schemathesis} sample inputs from the OpenAPI surface and check the HTTP status class; LLM-assisted successors~\cite{Kim2024RESTGPT,Kim2025LlamaRestTest,Stennett2025AutoRestTest} sharpen value synthesis but inherit the same oracle; LogiAgent~\cite{Zhang2025LogiAgent} asks an LLM to read each response body but discards the cross-service context. Three consequences hurt microservice deployments specifically. \emph{(G1) Soft errors slip through.} Enterprise endpoints frequently answer \texttt{HTTP 200 OK} with a body that flags a domain-level rejection (\texttt{status:0, data:null}); the failure evidence lives only in the body. \emph{(G2) Downstream failures are swallowed.} A gateway can answer \texttt{HTTP 200} while a service deeper in the call tree has \texttt{5xx}-errored and the caller's error handling masked it; the only evidence is a span off the response path, invisible to status, schema, and even body-level checks when the body looks clean. \emph{(G3) Internal endpoints fabricate state.} Generators that exercise every operation must invent values for IDs that only specific upstream calls can mint; a fabrication failure is then indistinguishable from a real defect.

MIST closes these gaps. Its differentiator versus AutoRestTest~\cite{Stennett2025AutoRestTest}, LogiAgent~\cite{Zhang2025LogiAgent}, and the grey-box MACROHIVE~\cite{Giamattei2022MACROHIVE,Giamattei2024MACROHIVE} is to treat the OpenTelemetry/Jaeger trace as the generation source \emph{and} the assertion target. We make three contributions, each shipping in the artifact:

\begin{itemize}\setlength{\itemsep}{1pt}
  \item \textbf{Root API Mode} (\S\ref{sec:rootmode}): drive only externally-reachable entry points; observe internal behaviour through traces. Closes G3 without instrumenting the SUT.
  \item \textbf{Sniper Strategy} (\S\ref{sec:sniper}): one fault per negative variant, drawn from 8 default categories plus a YAML applicability matrix. Each \texttt{(name, location)} slot --- path, query, header, cookie, body --- enrols separately. A \texttt{FaultMiner} extends the registry with SUT-specific categories via LLM prompting over OpenAPI descriptions and observed 4xx/5xx responses.
  \item \textbf{Trace Shape Oracle} (\S\ref{sec:traceoracle}): learned-then-checked invariant families per root API over the trace metadata that survives production PII-stripping. \textsc{ResponseEnvelope} attacks G1 (and subsumes the legacy soft-error rule cache); \textsc{HiddenDownstreamFailure}, label-free and LLM-free, attacks G2 by flagging a server-errored downstream span behind a 2xx entry.
\end{itemize}

\noindent A bundled demo runs end-to-end from one properties file on four microservice systems --- TrainTicket~\cite{Zhou2021TrainTicket}, Istio Bookinfo, Sock Shop, and Online Boutique --- from their own inputs with no code changes (\S\ref{sec:case}).

\section{Motivating Example}\label{sec:bg}

TrainTicket's \texttt{POST /api/v1/adminrouteservice/adminroute} takes a \texttt{startStation}, \texttt{endStation}, and \texttt{stationList}. On a Sniper-mutated negative variant whose end station is absent from the station list, the service answers \emph{HTTP 200} with body \texttt{\{"status":0, "msg":"start or end station not include in stationList.", "data":null\}}. A status-class oracle records the run as a pass: every span in the trace returns 200 and no span sets an OpenTelemetry error frame, so the only failure evidence is the response envelope. MIST's \textsc{ResponseEnvelope} invariant --- a one-shot LLM classification of the first unseen 2xx body value per API, cached thereafter --- catches the failure, and the trace pins the rejection to \texttt{ts-admin-route-service}. AutoRestTest's MARL reward~\cite{Stennett2025AutoRestTest} ignores 2xx bodies; LogiAgent's NL Validator~\cite{Zhang2025LogiAgent} sees the body but lacks the cross-service trace context that pins blame to a service.

A second, harder case carries \emph{no} body evidence. Under a real \texttt{ratings} outage, Istio Bookinfo's \texttt{GET /api/v1/products/\{id\}/reviews} still answers \texttt{HTTP 200}: the \texttt{reviews} service catches the \texttt{503} from \texttt{ratings} and degrades gracefully. The client sees success; the only evidence of failure is the swallowed \texttt{503} span deeper in the tree (Figure~\ref{fig:trace}). No status- or schema-level oracle can see it, and a body-reading oracle catches it only if the degraded body happens to leak a breadcrumb. MIST's \textsc{HiddenDownstreamFailure} invariant flags it structurally from the span alone (\S\ref{sec:case}, Table~\ref{tab:bookinfo}).

\section{Tool Architecture}\label{sec:arch}

\begin{figure*}[t]
  \centering
  \resizebox{\textwidth}{!}{\input{figures/architecture.tex}}
  \caption{MIST architecture and Maven module layout. \texttt{mist-core} owns all five architectural stages (spec ingest, semantic dependency registry, sequence generator, sniper strategy, trace shape oracle) and depends on no third-party source. \texttt{mist-cli} ships the launcher \texttt{mist.jar}, the JUnit/REST-Assured writer, and the test executor. \texttt{mist-llm} is LLM dispatch and call cache. Solid arrows are MIST-issued HTTP requests; the dashed arrow is the Jaeger trace pulled back per step by the Trace Shape Oracle.}
  \label{fig:arch}
\end{figure*}

MIST is a Maven reactor of three modules (Figure~\ref{fig:arch}). \texttt{mist-core} owns all five architectural stages described below and contains no third-party source code: the OpenAPI parser wrapper (\texttt{io.mist.core.spec.*}), the semantic dependency registry (\texttt{io.mist.core.registry.*}), the sequence generator (\texttt{io.mist.core.generation.MistGenerator}), the sniper fault registry (\texttt{io.mist.core.fault.*}), and the trace shape oracle (\texttt{io.mist.core.oracle.shape.*}) all live here. \texttt{mist-cli} ships the launcher \texttt{mist.jar}, the JUnit/REST-Assured writer, the test executor, and the SPI provider classes that let \texttt{mist-core} stay framework-agnostic. \texttt{mist-llm} is LLM dispatch and call cache. The build depends on REST-Assured, swagger-parser, Allure, and JUnit as ordinary Maven library artifacts --- every black-box REST tester does~\cite{MartinLopez2021RESTest,Arcuri2019EvoMasterTOSEM,Atlidakis2019RESTler} --- but the MIST repository does not vendor any forked third-party source.

\textbf{(i) Spec Ingestor} parses one OpenAPI spec (or aggregates per-service \texttt{/v3/api-docs}) and emits an MST configuration. The bundled TrainTicket spec carries 265 operations across 37 REST-exposed services (the distinct \texttt{/api/v1/} service prefixes).

\textbf{(ii) Semantic Dependency Registry} indexes producer/consumer pairs over spec and trace corpus. For every \texttt{Id}/\texttt{ID}/\texttt{uuid}-stemmed parameter, a 5-pass build mines the API and JSON path that historically produces a matching value.

\textbf{(iii) Sequence Generator (Root API Mode)} runs a 5-phase pipeline (Phase 2.5 dedup, shared-pool, Phase 3 weakly-connected-component shattering, Phase 3.5 dedup, Phase 4 decomposition). On the bundled TrainTicket trace corpus the pipeline collapses overlapping single-root scenarios into a smaller set of multi-root sequences. Root API Mode (\S\ref{sec:rootmode}) keeps gateway-entry calls and prunes internal spans; the writer emits one JUnit step per root call.

\textbf{(iv) Sniper Strategy} (\S\ref{sec:sniper}) builds an \texttt{Invalid\-Input\-Pool} per parameter, keyed by \texttt{PoolKey(name, location)} so same-named params at path/query/header/cookie/body are disjoint. The 8 default categories (TYPE\_MISMATCH, REGEX\_\allowbreak MISMATCH, SEMANTIC\_MISMATCH, OVERFLOW, EMPTY, NULL, SPECIAL\_CHARACTERS, BOUNDARY\_VIOLATION) are filtered through a YAML applicability matrix and extended at run-time by \texttt{FaultMiner}.

\textbf{(v) Trace Shape Oracle} (\S\ref{sec:traceoracle}) fetches the Jaeger trace after each emitted JUnit step and evaluates it against invariant families: four learned from a seed corpus of known-good runs (\textsc{SpanTreeShape}, \textsc{StatusPropagation}, \textsc{ResponseEnvelope}, and a \textsc{TimingEnvelope} invariant disabled by default) plus two evaluation-only structural invariants (\textsc{TargetAttribution}, \textsc{HiddenDownstreamFailure}) that need no learned state. \textsc{ResponseEnvelope} subsumes the legacy \texttt{SoftErrorRuleCache}.

\section{Design}\label{sec:innov}

\subsection{Root API Mode}\label{sec:rootmode}

Internal microservice endpoints presuppose state that only specific upstream calls can mint (an \texttt{orderId} the database knows, a session token not yet expired). A generator that drives those endpoints directly must fabricate the state, and a fabrication failure is indistinguishable from a real defect (G3). Root API Mode keeps only gateway-entry HTTP spans of each Jaeger scenario --- those with no HTTP parent --- and replays them externally; internal behaviour is observed through the captured trace. The mode is one boolean (\texttt{mst.gener\-ate.only.first.step}, default \texttt{true}). Trace-grounded generation is the angle AutoRestTest~\cite{Stennett2025AutoRestTest} cannot adopt (its SPDG is derived from OpenAPI names via GloVe embedding) and that MACROHIVE~\cite{Giamattei2022MACROHIVE} adopts only at the cost of deploying a service-mesh proxy per microservice; MIST consumes whatever OTel exporter the SUT already runs.

\subsection{Sniper Strategy}\label{sec:sniper}

A negative test that mutates several parameters at once leaves the oracle unable to blame a downstream anomaly on any specific cause; a single-fault test on a non-root call has the dual problem because the trace prefix itself is driven by other, possibly mutated, values. The Sniper Strategy (Alg.~\ref{alg:sniper}) tightens both axes: one parameter, one fault category, at the first root call.

\begin{algorithm}[t]
\caption{Sniper variant generation.}\label{alg:sniper}
\begin{algorithmic}[1]
\State $r \gets$ first root call in the scenario
\State $k \gets$ round-robin pick of \texttt{PoolKey(name, location)} on $r$;\ \  $c \gets$ fault category applicable to $k$'s schema
\State $v \gets pools[r][k][c].\textrm{nextRoundRobin}()$
\State lock $(r, k, c, v)$ on the variant; fill the rest from positive sources (shared pool, smart fetch, JIT bind)
\State record $(r, k, c, v)$ as the fault target
\end{algorithmic}
\end{algorithm}

\texttt{PoolKey(name, location)} is what lets same-named parameters at path/query/header/cookie/body enrol independently. A schema-aware applicability filter rejects nonsense (no 5000-char OVERFLOW on a boolean). \texttt{FaultMiner} extends the 8-category baseline with SUT-specific entries: when the OpenAPI description cites a numeric range or regex, or when a 4xx response cites a domain-specific rejection, the miner consults the LLM, validates the proposed category against the matrix, and persists it to \texttt{.mist/mined-fault-types.yaml}. The recorded $(r, k, c, v)$ tuple is what the report needs to attribute each failure to its mutation. Each picked value also carries a provenance tag (\emph{live}, \emph{cache}, \emph{LLM}, \emph{placeholder}, or \emph{mutated}); a single \emph{placeholder} tag anywhere in an ostensibly positive variant reclassifies the test as negative up front and re-ranks subsequent variants via Thompson sampling over the fault-target queue, reducing the false-positive failures that otherwise follow when no value could be grounded against the live SUT.

\subsection{Trace Shape Oracle}\label{sec:traceoracle}

\begin{figure*}[t]
  \centering
  \resizebox{\textwidth}{!}{\input{figures/trace_oracle.tex}}
  \caption{Captured Jaeger trace of \texttt{GET /api/v1/products/\{id\}/reviews} on Istio Bookinfo under a real \texttt{ratings} outage (committed: \texttt{bookinfo\_e2e\_traces/masked\_reviews\_ratings\_outage.json}). The client-facing entry returns \texttt{HTTP 200} --- \texttt{reviews} degrades gracefully --- yet a deeper \texttt{ratings} span server-errored (\texttt{503}, \texttt{otel.status\_code=ERROR}) and was swallowed. A status-, schema-, or body-only oracle records the run as a pass; the label-free \textsc{HiddenDownstreamFailure} invariant fires on the swallowed span alone.}
  \label{fig:trace}
\end{figure*}

The Trace Shape Oracle reaches the right verdict on Figure~\ref{fig:trace} by evaluating each captured trace against several invariant families:
\begin{itemize}\setlength{\itemsep}{1pt}
  \item \textsc{SpanTreeShape}: the trace tree matches the structural pattern recorded for the same root API; a missing internal hop surfaces even when every observed call returns 200.
  \item \textsc{StatusPropagation}: no descendant span carries \texttt{otel.\allowbreak status\_code=ERROR} or \texttt{http.status\_code}~$\geq 400$.
  \item \textsc{ResponseEnvelope}: body-pattern rules (success/failure sets, field-level checks). The first unseen 2xx primary-field value per API is classified by a single LLM call and cached at \texttt{.mist/trace-shape-invariants.json}; every later occurrence resolves from the cache. This is the invariant on which the \texttt{status:0, data:null} soft error of \S\ref{sec:bg} fails; it subsumes the legacy \texttt{SoftErrorRuleCache}.
  \item \textsc{HiddenDownstreamFailure}: label-free and LLM-free. When the client-facing entry span is 2xx but any deeper span server-errored (\texttt{http.status\_code}~$\geq 500$ or \texttt{otel.status\_code=ERROR}), the failure was swallowed and the invariant fires; a deeper \texttt{4xx} is treated as benign control flow. This is the signal that catches the Bookinfo case of Figure~\ref{fig:trace} and \S\ref{sec:case} (Table~\ref{tab:bookinfo}), whose response body is a clean 200.
\end{itemize}
Two further invariants round out the oracle. \textsc{TargetAttribution} is intent-conditioned: given the Sniper target $(r,k,c,v)$, it classifies whether the trace's leaf rejection landed on the attacked service/parameter or upstream (an advisory signal). A learned \textsc{TimingEnvelope} invariant also exists but is \emph{disabled by default}: in microservice deployments end-to-end latency is dominated by cold-cache, GC, and cluster-load variance that belongs to trace anomaly detection rather than functional testing. Every enabled invariant operates on trace metadata that survives the PII-stripping common to GDPR/HIPAA-compliant OTel exporters --- span tree, HTTP/OTel status codes, and one-shot body classification --- so MIST stays effective on production-realistic corpora where request/response bodies are redacted upstream. Caching bounds the LLM cost at roughly two calls per distinct API; the structural invariants (\textsc{SpanTreeShape}, \textsc{StatusPropagation}, \textsc{HiddenDownstreamFailure}) use no LLM at all. The oracle also matches the response \texttt{faultName} against the injected-fault registry to attribute confirmed failures to their $(r, k, c, v)$ mutation.

\section{Usage and Case Study}\label{sec:case}

The trace-oracle results reproduce \emph{offline} from a fresh clone --- no live SUT, no LLM:
\begin{lstlisting}[basicstyle=\scriptsize\ttfamily,frame=none]
$ mvn -DskipTests install
$ java -jar mist.jar .../trainticket-demo-noexec.properties
$ java -cp mist.jar evaluation/suts/bookinfo/OracleCheck.java \
    .../masked_reviews_ratings_outage.json "GET ...reviews"
\end{lstlisting}
The first command generates the cross-service JUnit tests from the bundled 265-operation spec and captured traces (no network); \texttt{OracleCheck} replays MIST's shipped \textsc{HiddenDownstreamFailure} invariant on a committed Bookinfo outage trace, firing where status/schema/body oracles pass. A companion harness \texttt{ResponseEnvelopeLiveCheck} reproduces the soft-error catch with one DeepSeek/Ollama call (committed transcript in the artifact). The \emph{live} demo --- executing the emitted tests against a deployed SUT, the 10-fault run, and the Bookinfo/Online~Boutique outage matrices --- additionally requires the SUT deployed, a reachable Jaeger, and a JDK (on Bookinfo the emitted test was compiled and launched by an external JDK, \S\ref{sec:rw}). The default LLM backend is DeepSeek \texttt{deepseek-chat} over an OpenAI-compatible shim; a local Ollama backend is also supported.

\textbf{Fault detection (TrainTicket).} On a 10-fault injected-fault corpus, MIST generated 15{,}036 test cases in ${\sim}6.5$\,h and detected all 10 faults, each confirmed against the injected-fault registry (run \texttt{trainticket\_twostage\_test\_42}, bundled in the artifact). Several are soft-error faults --- e.g.\ \textsc{Invalid\_Station\_Name}, which returns \texttt{HTTP 200} with \texttt{status:0} that a status-class oracle records as a pass --- the class the \textsc{ResponseEnvelope} invariant targets; its one-shot LLM classifier flipping such a body to a failure is reproduced offline by the committed \texttt{ResponseEnvelopeLiveCheck} harness. We do not report a head-to-head against other tools here; a controlled multi-tool comparison is reserved for the companion research paper (\S\ref{sec:rw}).

\textbf{Hidden downstream failure (Bookinfo, Online Boutique).} On Istio Bookinfo under a real \texttt{ratings} outage, MIST generated tests for every configured operation --- including \texttt{GET /api/v1/products/\{id\}/reviews} --- and executed them against the live SUT, with the trace oracle rendering the verdict per step. Table~\ref{tab:bookinfo} is the result. The masked \texttt{/reviews} call (row 2) returns \texttt{HTTP 200}, so a response-level oracle passes; yet \textsc{HiddenDownstreamFailure} fires on the swallowed \texttt{503} \texttt{reviews}$\to$\texttt{ratings} span and fails the test. The invariant does not over-claim: a direct \texttt{/ratings} call (row 3) is a loud \texttt{503} the status oracle already catches, and the same \texttt{/reviews} test goes silent when \texttt{ratings} is healthy (row 4) or absent from the call (row 1) --- sensitivity in row 2, specificity in rows 1, 3, 4.

The same invariant generalises to a second SUT over a different protocol. Google's Online Boutique renders ads from a non-critical \texttt{adservice}; with \texttt{adservice} scaled to zero its \texttt{frontend} still returns \texttt{HTTP 200} (the page renders without ads) while the swallowed \texttt{frontend}$\to$\texttt{adservice} gRPC call carries \texttt{otel.status\_code=ERROR} (status~14, \textsc{unavailable}). Run on the captured live traces, \textsc{HiddenDownstreamFailure} fires on 7 of the 12 captured outage traces --- every \texttt{frontend} trace that routed through the failed \texttt{adservice} --- and 0 of 12 healthy controls, at \textsc{warn} severity (an \texttt{otel}-error rather than an HTTP 5xx). A fresh re-capture reproduces this (24 of 40 outage traces flagged, all root-\texttt{200} with a swallowed \texttt{adservice} error; 0 of 30 healthy). Here the home-page body is an ordinary \texttt{200} page with \emph{no} error breadcrumb, so a body-reading oracle cannot see the failure at all; only the trace exposes it.

\textbf{Generality.} The same \texttt{java -jar mist.jar} flow runs on all four SUTs from their own inputs --- one OpenAPI-derived config, two properties files, captured traces --- with no code changes; the only per-SUT artifacts are inputs, not patches (e.g.\ on Online Boutique MIST generated 38 test cases and produced its report without crashing). The response-envelope (soft-error) oracle generalises too: on Sock Shop, a \texttt{catalogue-db} outage makes \texttt{GET /catalogue} return \texttt{HTTP 200} with a \texttt{\{status\_code:500\}} error body --- a soft error the oracle flags where a status-class oracle passes.

\section{Related Work and Limitations}\label{sec:rw}

\textbf{Related work.} MACROHIVE~\cite{Giamattei2022MACROHIVE,Giamattei2024MACROHIVE} reaches grey-box visibility by deploying a per-service mesh proxy; MIST achieves the same observation surface vendor-neutrally via OTel. AutoRestTest~\cite{Stennett2025AutoRestTest} explores operation/parameter/value/dependency/header axes with MARL agents over a GloVe-embedded dependency graph; LogiAgent~\cite{Zhang2025LogiAgent} asks an LLM to read each response body; RESTler~\cite{Atlidakis2019RESTler} fuzzes sequence dependencies inferred from OpenAPI response references; none ingest distributed traces. Distributed tracing originates with Dapper~\cite{Sigelman2010Dapper}, is standardised by OpenTelemetry~\cite{OpenTelemetry}, and trace-RCA work in production diagnostics (e.g.\ TraceRCA~\cite{Li2021TraceRCA}) uses traces as a post-hoc explanation; to our knowledge MIST is the first open-source REST API test generator to use the distributed trace as both a \emph{generation} input \emph{and} a first-class functional \emph{oracle}, as opposed to grey-box coverage signals or post-hoc RCA.

\textbf{Limitations.} MIST requires the SUT to export OTel/Jaeger traces; uninstrumented services are invisible. The demo runs on four SUTs, and the hidden-downstream phenomenon is shown on two (Bookinfo over HTTP, Online Boutique over gRPC); both are driven by a real availability outage rather than a malicious input --- eliciting it from input alone is harder, separate work. The structural invariant was isolated (the other shape invariants need per-SUT learned baselines), and the verdicts come from MIST's shipped invariant run on traces captured from the live SUTs; the Bookinfo headline additionally executed the MIST-generated test, compiled and launched by an external JDK rather than MIST's in-process path. The test source and the oracle are MIST's. A controlled multi-tool comparison against AutoRestTest, LogiAgent, and MACROHIVE across more systems~\cite{Gan2019DeathStarBench} is reserved for the companion research paper. This demo paper claims the tool exists, reproduces its trace-oracle results offline from one properties file and committed traces, and clears the engineering bar.
