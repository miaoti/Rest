\begin{abstract}
Black-box REST API testers sample inputs from the OpenAPI spec and stop at the HTTP status class, missing failures that surface only across services: a \emph{soft error} returned in a 2xx body, and a \emph{hidden downstream failure} where the gateway returns 2xx while a deeper service has 5xx-errored and the error was swallowed. We present \textbf{MIST} (Microservice Integration \& Scenario Tester), an open-source tool that turns OpenTelemetry/Jaeger traces and OpenAPI specs into runnable cross-service tests and checks them with a \emph{trace-shape oracle}. MIST drives only externally-reachable entry points, reading internal behaviour off the trace (\emph{Root API Mode}), and injects one fault per negative variant (\emph{Sniper Strategy}). Its \textsc{HiddenDownstreamFailure} invariant --- label-free and LLM-free --- fires when a clean 2xx hides a server-errored downstream span, caught structurally from the trace. A bundled demo runs on four microservice systems (TrainTicket~\cite{Zhou2021TrainTicket}, Istio Bookinfo, Sock Shop, Online Boutique) from one properties file with no source changes. On TrainTicket it scales to 15{,}036 generated tests (all 10 injected faults detected via the fault registry); on Bookinfo and Online Boutique its oracle catches a real failure swallowed behind a \texttt{200} --- over HTTP and gRPC --- that status-, schema-, and body-level oracles pass, and reproduces offline from committed traces with no SUT or LLM. Source: \url{https://github.com/miaoti/Rest/}. Screencast: \todo{SCREENCAST-URL}.
\end{abstract}

\section{Introduction}\label{sec:intro}

Modern REST API testers are spec-bound and oracle-light. Spec-only generators~\cite{Arcuri2019EvoMasterTOSEM,Atlidakis2019RESTler,MartinLopez2021RESTest,Liu2022MoRest,Kim2023ARATRL,Corradini2024DeepREST,HatfieldDodds2022Schemathesis} sample inputs from the OpenAPI surface and check the HTTP status class; LLM-assisted successors~\cite{Kim2024RESTGPT,Kim2025LlamaRestTest,Stennett2025AutoRestTest} sharpen value synthesis but inherit the same oracle; LogiAgent~\cite{Zhang2025LogiAgent} asks an LLM to read each response body but discards the cross-service context. Three consequences hurt microservice deployments specifically. \emph{(G1) Soft errors slip through.} Enterprise endpoints frequently answer \texttt{HTTP 200 OK} with a body that flags a domain-level rejection (\texttt{status:0, data:null}); the failure evidence lives only in the body. \emph{(G2) Downstream failures are swallowed.} A gateway can answer \texttt{HTTP 200} while a service deeper in the call tree has \texttt{5xx}-errored and the caller's error handling masked it; the only evidence is a span off the response path, invisible to status, schema, and even body-level checks when the body looks clean. \emph{(G3) Internal endpoints fabricate state.} Generators that exercise every operation must invent values for IDs that only specific upstream calls can mint; a fabrication failure is then indistinguishable from a real defect.

MIST closes these gaps. Its differentiator versus AutoRestTest~\cite{Stennett2025AutoRestTest}, LogiAgent~\cite{Zhang2025LogiAgent}, and the grey-box MACROHIVE~\cite{Giamattei2022MACROHIVE,Giamattei2024MACROHIVE} is to treat the OpenTelemetry/Jaeger trace as the generation source \emph{and} the assertion target. We make three contributions, all shipping in the artifact. \textbf{Root API Mode} (\S\ref{sec:rootmode}) drives only externally-reachable entry points and observes internal behaviour through traces, closing G3 without instrumenting the SUT. \textbf{Sniper Strategy} (\S\ref{sec:sniper}) injects one fault per negative variant --- keyed by \texttt{(name, location)} so each parameter slot enrols separately --- from nine default categories plus a YAML applicability matrix, extended at run time by a \texttt{FaultMiner}. The \textbf{Trace Shape Oracle} (\S\ref{sec:traceoracle}) checks learned-then-checked invariant families over the trace metadata that survives production PII-stripping: \textsc{ResponseEnvelope} attacks G1 with a one-shot LLM body classifier, and \textsc{HiddenDownstreamFailure} --- label-free and LLM-free --- attacks G2 by flagging a server-errored downstream span behind a 2xx entry.

\noindent A bundled demo is configured per system by one properties file on four microservice systems --- TrainTicket~\cite{Zhou2021TrainTicket}, Istio Bookinfo, Sock Shop, and Online Boutique --- from their own inputs with no source changes (\S\ref{sec:case}).

\section{Tool Architecture}\label{sec:arch}

\begin{figure*}[t]
  \centering
  \resizebox{\textwidth}{!}{\input{figures/architecture.tex}}
  \caption{MIST architecture: \texttt{mist-core} (the five stages, no third-party source), \texttt{mist-cli} (launcher \texttt{mist.jar}, JUnit/REST-Assured writer, executor), \texttt{mist-llm} (LLM dispatch + cache). Solid arrows: MIST HTTP requests; dashed: the per-step Jaeger trace.}
  \label{fig:arch}
\end{figure*}

MIST is a Maven reactor of three modules (Figure~\ref{fig:arch}). \texttt{mist-core} owns all five architectural stages described below and contains no third-party source code: the OpenAPI parser wrapper (\texttt{io.mist.core.spec.*}), the semantic dependency registry (\texttt{io.mist.core.registry.*}), the sequence generator (\texttt{io.mist.core.generation.MistGenerator}), the sniper fault registry (\texttt{io.mist.core.fault.*}), and the trace-shape oracle (\texttt{io.mist.core.oracle.shape.*}) all live here. \texttt{mist-cli} ships the launcher \texttt{mist.jar}, the JUnit/REST-Assured writer, the test executor, and the SPI provider classes that let \texttt{mist-core} stay framework-agnostic. \texttt{mist-llm} is LLM dispatch and call cache. The build depends on REST-Assured, swagger-parser, Allure, and JUnit as ordinary Maven library artifacts --- every black-box REST tester does~\cite{MartinLopez2021RESTest,Arcuri2019EvoMasterTOSEM,Atlidakis2019RESTler} --- but the MIST repository does not vendor any forked third-party source.

\textbf{(i) Spec Ingestor} parses one OpenAPI spec (or aggregates per-service \texttt{/v3/api-docs}) and emits an MST configuration. The bundled TrainTicket spec carries 265 operations across 37 REST-exposed services (the distinct \texttt{/api/v1/} service prefixes).

\textbf{(ii) Semantic Dependency Registry} indexes producer/consumer pairs over spec and trace corpus. For every \texttt{Id}/\texttt{ID}/\texttt{uuid}-stemmed parameter, a 5-pass build mines the API and JSON path that historically produces a matching value.

\textbf{(iii) Sequence Generator (Root API Mode)} runs a 5-phase pipeline (Phase 2.5 dedup, shared-pool, Phase 3 weakly-connected-component shattering, Phase 3.5 dedup, Phase 4 decomposition). On the bundled TrainTicket trace corpus the pipeline collapses overlapping single-root scenarios into a smaller set of multi-root sequences. Root API Mode (\S\ref{sec:rootmode}) keeps each scenario's externally-reachable entry call and prunes internal spans; the writer emits one JUnit step per root call.

\textbf{(iv) Sniper Strategy} (\S\ref{sec:sniper}) builds an \texttt{Invalid\-Input\-Pool} per parameter, keyed by \texttt{PoolKey(name, location)} so same-named params at path/query/header/cookie/body are disjoint. The 9 default categories (TYPE\_MISMATCH, REGEX\_\allowbreak MISMATCH, SEMANTIC\_MISMATCH, OVERFLOW, EMPTY\_\allowbreak INPUT, NULL\_\allowbreak INPUT, SPECIAL\_\allowbreak CHARACTERS, BOUNDARY\_\allowbreak VIOLATION, ENUM\_\allowbreak VIOLATION) are filtered through a YAML applicability matrix and optionally extended by \texttt{FaultMiner} (disabled by default).

\textbf{(v) Trace Shape Oracle} (\S\ref{sec:traceoracle}) fetches the Jaeger trace after each emitted JUnit step and evaluates it against invariant families: four learned from a seed corpus of known-good runs (\textsc{SpanTreeShape}, \textsc{StatusPropagation}, \textsc{ResponseEnvelope}, and a \textsc{TimingEnvelope} invariant disabled by default) plus two evaluation-only structural invariants (\textsc{TargetAttribution}, \textsc{HiddenDownstreamFailure}) that need no learned state.

\section{Design}\label{sec:innov}

\subsection{Root API Mode}\label{sec:rootmode}

Internal endpoints presuppose state only specific upstream calls can mint (an \texttt{orderId} the database knows, a live session token); driving them directly forces the generator to fabricate it, and a fabrication failure is indistinguishable from a real defect (G3). Root API Mode (one boolean, default \texttt{true}) instead keeps each trace's externally-reachable entry call --- the parentless span left after skipping mesh/ingress routing spans (service name containing \texttt{gateway}, or a wildcard \texttt{VERB /*}) --- replays it externally, and observes internals through the captured trace, consuming whatever OTel exporter the SUT runs. Unlike AutoRestTest's GloVe-embedded SPDG~\cite{Stennett2025AutoRestTest} or MACROHIVE's per-service mesh proxy~\cite{Giamattei2022MACROHIVE}, this adds no instrumentation.

\subsection{Sniper Strategy}\label{sec:sniper}

Mutating several parameters at once leaves the oracle unable to blame an anomaly on any specific cause; a single-fault test on a non-root call has the dual problem (its trace prefix is driven by other, possibly mutated, values). The Sniper Strategy fixes both: at the first root call it locks one round-robin-picked parameter to one applicable fault category and value, recorded as the fault target $(r,k,c,v)$, and fills the rest from positive sources (shared pool, smart fetch, JIT bind).

\texttt{PoolKey(name, location)} lets same-named parameters at path/query/header/cookie/body enrol independently; a schema-aware filter rejects nonsense (no 5000-char \textsc{overflow} on a boolean). The recorded $(r, k, c, v)$ tuple attributes each failure to its mutation. A \emph{placeholder} provenance tag --- no value could be grounded against the live SUT --- reclassifies an ostensibly positive variant as negative up front, cutting false positives. Opt-in, \texttt{FaultMiner} mines SUT-specific categories beyond the nine defaults from OpenAPI descriptions and observed 4xx/5xx bodies, for manual promotion.

\subsection{Trace Shape Oracle}\label{sec:traceoracle}

\begin{figure*}[t]
  \centering
  \resizebox{\textwidth}{!}{\input{figures/trace_oracle.tex}}
  \caption{\texttt{GET /api/v1/products/\{id\}/reviews} on Istio Bookinfo under a real \texttt{ratings} outage (committed trace, IDs anonymised). The entry returns \texttt{HTTP 200} (\texttt{reviews} degrades gracefully), yet a deeper \texttt{ratings} span server-errored (\texttt{503}, \texttt{otel.status\_code=ERROR}) and was swallowed --- invisible to status/schema/body oracles, caught by \textsc{HiddenDownstreamFailure} alone.}
  \label{fig:trace}
\end{figure*}

The Trace Shape Oracle reaches the right verdict on Figure~\ref{fig:trace} by evaluating each captured trace against several invariant families. \textsc{SpanTreeShape} checks the trace tree against the pattern recorded for the same root API, so a missing internal hop surfaces even when every observed call returns \texttt{200}. \textsc{StatusPropagation} flags any span whose status code falls outside the per-depth set learned from known-good runs --- e.g.\ an \texttt{otel.\allowbreak status\_code=ERROR} or an unexpected \texttt{http.\allowbreak status\_code}. \textsc{ResponseEnvelope} applies body-pattern rules over learned success/failure value sets: the first unseen 2xx primary-field value per API is classified by one LLM call and cached, and it fails on a \texttt{status:0, data:null} soft error (a clean 2xx body flagging a domain rejection). \textsc{HiddenDownstreamFailure} --- label-free, LLM-free, opt-in --- fires when the client-facing entry returned 2xx but a deeper span server-errored (\texttt{http.\allowbreak status\_code}~$\geq 500$ or \texttt{otel.\allowbreak status\_code=ERROR}); a deeper \texttt{4xx} is benign. An HTTP-5xx swallow fails the test (\textsc{error}); an \texttt{otel}-only error (the gRPC case) is non-blocking \textsc{warn}. Because the untraced external client leaves the entry's own inbound span frequently absent, the live path anchors on the test's injected client status, using trace topology only for offline replay.
\textsc{TargetAttribution} (advisory) classifies whether the trace's leaf rejection landed on the attacked Sniper target $(r,k,c,v)$ or upstream; a learned \textsc{TimingEnvelope} exists but is disabled by default (microservice latency variance belongs to anomaly detection, not functional testing). Each invariant's fire/no-fire decision rests on the trace \emph{graph} and status codes --- which production PII pipelines preserve while redacting attribute \emph{values} --- so MIST works on corpora with redacted bodies; only \textsc{ResponseEnvelope} needs an unredacted body. The structural invariants use no LLM.

\section{Usage and Case Study}\label{sec:case}

The \textsc{HiddenDownstreamFailure} verdicts reproduce \emph{offline} from a fresh clone --- no live SUT, no LLM:
\begin{lstlisting}[basicstyle=\scriptsize\ttfamily,frame=none]
$ mvn -DskipTests install
$ java -jar mist.jar .../trainticket-demo-noexec.properties
$ java -cp mist.jar evaluation/suts/bookinfo/OracleCheck.java \
    .../masked_reviews_ratings_outage.json "GET ...reviews"
\end{lstlisting}
The first command generates the cross-service JUnit tests from the bundled 265-operation spec and captured traces (no network); \texttt{OracleCheck} replays the shipped \textsc{HiddenDownstreamFailure} invariant on a committed Bookinfo outage trace, firing where status/schema/body oracles pass, and \texttt{Response\allowbreak EnvelopeLiveCheck} reproduces the soft-error catch with one DeepSeek/Ollama call (committed transcript). The \emph{live} demo --- the 10-fault run and the Bookinfo/Online~Boutique outage matrices --- additionally needs the SUT, a reachable Jaeger, and a JDK (MIST compiles and runs the emitted tests in-process, falling back to an external \texttt{javac} only on a JRE host, \S\ref{sec:rw}).

\textbf{Fault detection (TrainTicket).} MIST generated 15{,}036 test cases in ${\sim}6.5$\,h on a 10-fault corpus; all 10 are detected via the injected-fault registry --- the self-instrumented SUT echoes the injected fault name, which MIST matches (run \texttt{trainticket\_\allowbreak twostage\_\allowbreak test\_42}, bundled). The trace-shape oracle is evaluated independently and did not drive these registry confirmations. Several faults are soft errors --- e.g.\ \textsc{Invalid\_Station\_Name} (\texttt{HTTP 200}, \texttt{status:0}) that a status-class oracle passes --- the class \textsc{ResponseEnvelope} targets; its one-shot LLM classifier flipping such a body to a failure is shown by the committed \texttt{Response\allowbreak EnvelopeLiveCheck} harness (one LLM call).

\textbf{Hidden downstream failure (Bookinfo, Online Boutique).} On Istio Bookinfo under a real \texttt{ratings} outage, MIST generated tests for every operation and executed them against the live SUT in one in-process \texttt{java -jar mist.jar} run (generate, compile, execute, oracle --- one JVM). In Table~\ref{tab:bookinfo}, the masked \texttt{/reviews} call (row 2) returns \texttt{HTTP 200}, so a response-level oracle passes, yet \textsc{HiddenDownstreamFailure} fires at \textsc{error} on the swallowed \texttt{503} \texttt{reviews}$\to$\texttt{ratings} span and fails the test red (committed report); the other rows (caption) confirm it does not over-fire.

The invariant generalises to a second protocol. With Online Boutique's non-critical \texttt{adservice} scaled to zero, \texttt{frontend} still returns \texttt{HTTP 200} while the swallowed \texttt{frontend}$\to$\texttt{adservice} gRPC call carries \texttt{grpc.status\_code=14} and \texttt{otel.status\_code=ERROR}; its \texttt{http.status\_code} is a misleading \texttt{200} (the HTTP/2 transport succeeded, the RPC failed), so the invariant fires on the \texttt{otel} signal, not HTTP. The in-process run generated and executed 579 tests and \textsc{HiddenDownstreamFailure} fired (at \textsc{warn} --- \texttt{otel}-only, no HTTP 5xx) on the swallowed call, each finding tied to a generated test and marker trace (committed report). A controlled replay over captured traces quantifies it: 7 of 12 outage traces fire (those routed through the failed \texttt{adservice}) and 0 of 12 healthy, replicated by a larger re-capture (24/40 outage, 0/30 healthy). The home-page body is a clean \texttt{200} with no breadcrumb; only the trace exposes the failure.

\textbf{Generality.} The same \texttt{java -jar mist.jar} flow runs on all four SUTs from their own inputs --- one OpenAPI-derived config, one properties file, captured traces --- with no source changes; per-SUT artifacts are inputs, not patches. MIST's LLM-backed soft-error body check generalises too: on Sock Shop, a \texttt{catalogue-db} outage makes \texttt{GET /catalogue} return \texttt{HTTP 200} with a \texttt{\{status\_code:500\}} body --- a soft error it flags where a status-class oracle passes.

\section{Related Work and Limitations}\label{sec:rw}

\textbf{Related work.} MACROHIVE~\cite{Giamattei2022MACROHIVE,Giamattei2024MACROHIVE} reaches grey-box visibility by deploying a per-service-mesh proxy; MIST achieves the same observation surface vendor-neutrally via OTel. AutoRestTest~\cite{Stennett2025AutoRestTest} explores operation/parameter/value/dependency/header axes with MARL agents over a GloVe-embedded dependency graph; LogiAgent~\cite{Zhang2025LogiAgent} asks an LLM to read each response body; RESTler~\cite{Atlidakis2019RESTler} fuzzes sequence dependencies inferred from OpenAPI response references; none ingest distributed traces. Distributed tracing originates with Dapper~\cite{Sigelman2010Dapper}, is standardised by OpenTelemetry~\cite{OpenTelemetry}, and trace-RCA / trace-anomaly work in production diagnostics (e.g.\ TraceRCA~\cite{Li2021TraceRCA}, Nezha~\cite{Yu2023Nezha}) uses the trace as a post-hoc, usually learned, explanation of an incident. Trace-based testing tools such as Tracetest~\cite{Tracetest} do assert over spans, but require human-authored, per-test span assertions and neither generate tests nor mine traces to drive generation. MIST instead closes the \emph{generation}$\to$\emph{oracle} loop inside a black-box REST API test generator, using the distributed trace as both a generation input and a first-class functional oracle without instrumenting the SUT; its \textsc{HiddenDownstreamFailure} oracle is label-free --- no authored assertions and no learned baseline. To our knowledge it is the first open-source REST API test generator to do so, as opposed to relying on grey-box coverage signals or post-hoc RCA.

\textbf{Limitations.} MIST requires the SUT to export OTel/Jaeger traces; uninstrumented services are invisible. The demo runs on four SUTs, and the hidden-downstream phenomenon is shown on two (Bookinfo over HTTP, Online Boutique over gRPC); both are driven by a real availability outage rather than a malicious input --- eliciting it from input alone is harder, separate work. The structural invariant was isolated (the other shape invariants need per-SUT learned baselines). MIST's full in-process pipeline --- generating, compiling, and executing the tests and running the oracle in one JVM --- fires the invariant on both live SUTs: Online Boutique over gRPC (\textsc{warn}) and Bookinfo over HTTP (\textsc{error}, failing the test red); the committed run reports are in the artifact. (On a JRE-only host, MIST falls back to an external \texttt{javac} for the compile step only.) A controlled multi-tool comparison against AutoRestTest, LogiAgent, and MACROHIVE across more systems~\cite{Gan2019DeathStarBench} is reserved for the companion research paper. This demo paper claims the tool exists, reproduces its trace-oracle results offline from one properties file and committed traces, and clears the engineering bar.
